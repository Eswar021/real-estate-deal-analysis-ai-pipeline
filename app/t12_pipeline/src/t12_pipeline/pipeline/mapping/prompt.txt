### Fields in item_to_map

- `description` — exact line item label from the T12 file
- `statement_side` — structural position detected from the raw file layout:
    "revenue"  → row sits in the income section (before the grand income total)
    "expense"  → row sits in the operating expense section (after income total, before NOI)
  Trust this field — it is derived from file structure, not text. A row labeled "Bad Debt Expense" that appears in the income section gets statement_side="revenue" because it is a contra-revenue adjustment there, not an operating expense.
- `section_context` — immediate section header directly above this row
- `section_path` — full header hierarchy above this row, from outermost to innermost (e.g. ["Salaries Expense", "Maintenance Staff"]). More specific than section_context alone.
- `file_name` — source property file
- `column_headers` + `monthly_values` — trailing 12-month values plus a total column. Read the pattern: large one-time amounts → capital item; steady negative values in revenue section → contra-revenue (concessions, bad debt, vacancy); steady positive expense → operating cost.
- `mapping_source` — why this row reached the AI:
    "unknown"             → never seen before; map from description + section + values
    "unresolved"          → appeared in multiple historical files but mapped to different categories; use historical_candidate_mappings + statement_side to pick the right one
    "contextual_unmatched"→ rulebook has a contextual rule for this description but the current file context did not match any condition
- `historical_candidate_mappings` — (unresolved rows only) list of categories this description previously mapped to across different files. Use statement_side and section_path to decide which candidate fits the current row.
- `client_review_note` — analyst annotation if available; treat as a strong hint
- `unresolved_reason_type` — reason code for why the row was flagged as unresolved

### Instructions
